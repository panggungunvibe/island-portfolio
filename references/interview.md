# 制作前的访谈

每轮只问一个主要问题，不一次发送完整问卷。不以原作者的名字、职业、项目、文章、研究、截图或演示履历举例，不从历史记忆推定当前用户的经历。只复用 UI 和展示方式。问题中的分类不是对用户经历的断言。

正常流程共 8 个主要问题：可选 Star 1 个、身份 1 个、四部分素材各 1 个、网站命名 1 个、最终确认 1 个。Star 已问过则 7 个；用户已主动回答的直接跳过。补问只用于影响准确呈现的缺口，不把下面的问题一次性甩给用户。

## 0. 可选 Star

沿用 SKILL.md 的明确授权问题与 [Star 操作流程](star.md)。同意才尝试操作并核验；拒绝、跳过、无工具或失败都继续制作。不在普通素材问题中重复展示作者账号。

## 1. 身份

身份题从 [identity-question.json](identity-question.json) 读取，下面是完整的固定题面：

“你现在是什么状态？”

| 选项 | 仅在问答工具要求 description 时使用的小字 |
|---|---|
| 学生 | 目前以学习为主。 |
| 已经工作 | 目前以工作为主。 |
| 混合身份 | 同时有多种身份，或不完全符合前两项。 |

工具不要求 description 时，只显示三个选项，不加小字。禁止把 description 当成个性化解释区；不要添加姓名、平台账号、公司、岗位、项目、转型经历或身份判断。发送前核对实际工具参数中的问题、选项标题和 description，均来自固定题面；不只是检查问题标题。问答工具支持自由填写时保留用户自行补充的入口，但不替用户填入背景。

学生用学生分类；已经工作或混合身份用非学生分类，不追加身份细分问卷。用户明确要求以学生身份展示时使用学生分类。

## 2. 固定四个部分，依次收集

只展示对应的一组：“我们从以下四个方面展示你的个人作品集，接下来逐个收集你的内容。”这是一段说明，不是另一个分类选择题。不要说“营地”。

| 学生 | 非学生（已经工作／混合身份） |
|---|---|
| 项目与实习经历 | 工作项目经历 |
| 科研项目 | 自媒体内容 |
| 社团与志愿者活动 | Vibe Coding 作品 |
| 自媒体与 Vibe Coding 作品 | 科研与个人研究项目 |

学生依次问：
1. “项目与实习经历：你有哪些想展示的项目或实习经历？”
2. “科研项目：你有哪些想展示的研究或科研经历？”
3. “社团与志愿者活动：你参加过哪些想展示的活动？”
4. “自媒体与 Vibe Coding 作品：你有哪些想展示的文章、视频，或用 AI 辅助编程制作的网站、工具？”

非学生依次问：
1. “工作项目经历：你有哪些想展示的工作或实践项目？”
2. “自媒体内容：你有哪些想展示的文章、视频或其他内容作品？”
3. “Vibe Coding 作品：你有哪些用 AI 辅助编程制作的网站、工具或应用想展示？”
4. “科研与个人研究项目：你有哪些想展示的科研经历或个人研究？”

每问一部分，附一句：“截图、链接、文字描述都可以，不必排版；没有这类内容也可以直接说没有。”收齐当前部分再问下一部分。不要把这些分类变成预填项目，也不要从模板补充用户没有提供的内容。

### 缺少材料时

- 用户明确没有：记录为已回答、无内容，保持四部分结构，生成时该部分显示“暂无展示内容”。这不是一个项目条目，不放入时间线或成果统计。
- 用户尚未回答：记为待收集，不当作无内容，更不能拿演示项目补齐。
- 用户主动要求替换分类：按其要求调整，但不在开头主动追加分类问卷。
- 缺图片或链接：真实文字描述足以展示，不制作假截图和假链接。

### 只按需追问

优先从用户给的材料提取标题、时间、背景、个人角色、行动与结果。有缺口且影响准确性才补问，例如“这个项目中你主要负责哪部分？”或“这个数字是个人成果还是团队成果？”涉及科研时按需确认题目、本人贡献与研究结果。不开额外的履历问卷，不为了丰富页面追问无关隐私或索要未授权材料。

## 3. 网站名字

“你想给网站起什么名字？也可以让我根据刚才提供的经历推荐几个。”

用户已经给了名字就跳过；需要建议时给 2–3 个并等其选择。建议仅依据其本次材料，不使用作者或模板人物的称呼。用户没有提供个人称呼时，用确认的网站名作为标题即可，不猜真名、不额外强制询问身份信息。简介根据材料起草，放到最后一并确认。

## 4. 正式 coding 前确认

“这是根据你提供的材料整理的网站名、简介和四部分内容，这样可以开始制作吗？”
- 可以，开始制作
- 我想调整

摘要列出每部分的真实条目与素材来源，无内容的明确标注“暂无展示内容”，未回答的标为待收集。先完成所有部分的收集及名称确认，再写个人内容数据和生成网站。用户明确授权按完整已提供素材继续时可视为确认，不重复追问。

制作前可阅读 Skill、核对资料与记录访谈，但不提前用模板人物内容生成“用户作品集”。

## 状态记录

在用户项目的 `portfolio-intake.md` 记录身份、分类、各部分状态（待收集／已提供／明确无内容）、素材来源、网站名、简介确认和最终确认。已有回答不重复问。个人材料不要写回 Skill 安装目录。
