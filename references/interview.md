# 选择题访谈

每轮最多问一个主要问题。开头只确认身份，然后直接推荐四个展示部分并开始收集内容，不连问用途、岗位、网站名和分类。面向用户统一说“部分”或“方面”，不要用“营地”、布局类型或其他实现术语。用户一次性给了充分材料，就记录并跳过已回答项。

## 0. 可选支持

遵循 SKILL.md 的明确授权问题与 [Star 操作流程](star.md)。同意后执行并核验，不能只展示链接就说已完成；拒绝、无授权工具或未回答都继续制作，不影响后续推荐。

## 1. 只确认身份

固定使用下面这道中性问题，保持三个选项的文字与顺序：

“你现在是什么状态？”
- 学生
- 已经工作
- 混合身份

允许用户自由补充其他状态；“混合身份”不预设具体组合，选择后再按需要了解其想展示的经历。

问题和选项中不写创作者或用户的姓名、账号、公司、岗位及过往经历，不加“我了解到你……”这类括号说明，不把“学生”替换成推测出的职业。即使有历史记忆，也不要据此改写这道问题。只有用户在本次制作中已明确回答身份，才记录并跳过。后续个性化建议只依据用户为本次作品集提供或确认的材料。

## 2. 直接给出四个展示部分

按已选身份展示对应的一组，不把所有身份的表格都发给用户：

| 身份 | 默认四个部分 |
|---|---|
| 学生 | 项目与实习经历 / 科研项目 / 社团与志愿者活动 / 自媒体与 Vibe Coding 作品 |
| 已经工作 | 工作项目经历 / 自媒体内容 / Vibe Coding 作品 / 科研与个人研究项目 |
| 混合身份 | 工作与实践项目 / 自媒体内容 / Vibe Coding 与科研作品 / 志愿者与社团活动 |

用简单的话介绍：“我们先从这四个方面展示你的个人作品集：……”并列出该身份的四个部分，再说明“没有的可以换成其他经历，也可以只保留三个部分。”这些是可调整的内容分类，不代表用户一定有对应经历。不额外要求填写一轮分类问卷，也不需要先批准这四项才能发素材。

紧接着只问第一部分的内容，例如已工作用户：“先从工作项目经历开始，你有哪些想展示的项目？截图、链接或简单描述都可以；如果没有这类经历，告诉我想换成什么。”

用户改名或替换时直接更新。没有科研可以换成志愿者活动等真实内容，不坚持身份默认分类。用户已经给出了想展示的方向时，沿用其选择，不覆盖。默认四个部分；只有三类就保留三个，不硬凑第四个，也不擅自扩到五个。

## 3. 一次收集一个部分

每个部分用它的实际名称提问，例如：“科研项目这部分，你有哪些想展示的内容？截图、链接或简单描述都可以，不必排版。”

从现有材料中提取以下项，只追问缺失且影响表达的内容：
- 标题、时间、背景和对象。
- 你的角色、具体做了什么，与团队成果的区别。
- 交付物、结果、指标的时间和定义；无数字可用定性反馈。
- 截图/封面/现场照片/论文/作品链接；确认可公开部分。
- 希望呈现哪段判断或复盘；只给链接且不可访问时请用户补内容摘要。

只有不清楚是否还要补材料时，才问：“这部分还有想补充的吗？”
- 已给完，继续下一个
- 还要补充
- 这部分不合适，换一个方向

不用等到每个字段填满。一个真实条目有标题和描述，就可以做文字展品；缺图不生成假截图。未说明排名的活动展示序号，不把序号包装成奖项。

### 按需补充，不整套追问

先从用户材料提取信息，只追问会影响准确呈现的缺口。下面是整理线索，不是需要逐题问完的问卷。

- 内容：面向谁？主要讲什么？有什么截图数据？复盘可用“为什么选题—关键取舍—结果—下次调整”。
- 项目：背景—目标—角色—行动—结果；标明某项数字是目标完成率、增长率还是绝对量。
- 科研：完整题目、作者、来源、问题/方法/发现、本人贡献；摘要和进一步推断分开。
- 活动：活动名、团队或个人角色、产出、结果；没获奖也能展示。

## 4. 材料收齐后再定名字

此时再问“网站想叫什么？你可以自己取名，也可以让我根据这些经历给你几个建议。”用户已给名字就不再问；需要建议时提供 2–3 个，等其选择，不套用示例名字。简介依据已提供材料起草，并入最终方案一起确认。

默认作为简历的视觉补充，不在开头另问展示对象或目标岗位。只有材料取舍确实依赖用途且用户尚未说明时，才简短补问。

## 5. 开工前的内容摘要

用小表列出：名字、简介、模块名称、展示形式、已有条目数、缺口。一次确认即可：
- 按这个方案生成
- 我想调整（自由填写）

所有模块先完成材料收集，再开工 coding；不要用户只给第一个模块，就把余下模块塞进示例内容交付。若用户已明确让你按当前素材直接制作，这可作为确认，不重复询问。

## 状态记录建议

`portfolio-intake.md` 保存在用户项目中：身份/目标、Star 是否已问（不记录凭据）、名称状态、选定模块、各模块材料来源/就绪状态、最终确认。用户新素材只更新相关模块。
