# 选择题访谈

按依赖顺序进行，不一次甩出全部问题。用户一次性给了充分材料，就记录并跳过已回答项。

## 0. 可选支持

遵循 SKILL.md 的一次性 Star 邀请。安装阶段即使没有回答也继续；不把用户的拒绝带入后续推荐。

## 1. 身份与目标

固定使用下面这道中性问题，保持三个选项的文字与顺序：

“你现在是什么状态？”
- 学生
- 已经工作
- 混合身份

允许用户自由补充其他状态；“混合身份”不预设具体组合，选择后再按需要了解其想展示的经历。

问题和选项中不写创作者或用户的姓名、账号、公司、岗位及过往经历，不加“我了解到你……”这类括号说明，不把“学生”替换成推测出的职业。即使有历史记忆，也不要据此改写这道问题。只有用户在本次制作中已明确回答身份，才记录并跳过。后续个性化建议只依据用户为本次作品集提供或确认的材料。

“这座网站主要给谁看？”
- 招聘方：配合简历，争取面试
- 合作方：看作品、聊合作
- 同行与朋友：介绍自己和长期记录

若已给出目标岗位，优先使用已有信息。否则可简短补问关注的岗位/合作方向，不把面试机会当作保证。

## 2. 四个默认营地

| 身份 | 四个默认方向 |
|---|---|
| 学生 | 项目与实习 / 科研与课程 / 社团与志愿 / 内容与创作 |
| 已工作 | 工作与项目 / 内容与作品 / 研究与观察 / 挑战与活动 |
| 混合身份 | 代表作品 / 实践项目 / 学习与研究 / 社区与挑战 |

“先用这四个方向吗？”
- 就用这四个
- 保留四个，但替换或改名（自由填写）
- 我只有三个方向（指出保留哪三个）

名称可以是“挑战营地”，内容则是黑客松、社团、公益或其他实际经历。不用模块名推断用户做过什么。展示布局也不与名称绑定。

## 3. 网站命名

“网站想叫什么？”
- 我自己命名（填写名字）
- 根据我的经历给我 2–3 个建议

用户选建议时，先获得至少一句自我描述再提名：如“林的观察站”“小夏的实践岛”“远航手记”。建议是建议，等用户选定。允许自定义副标题与一句话介绍；如果用户不想写，依据真实材料起草后一起确认。

## 4. 一次收集一个模块

每个模块先问：“这个营地有哪些想展示的经历？截图、链接、文字都可以，已有的尽量发给我，不必排版。”

从现有材料中提取以下项，只追问缺失且影响表达的内容：
- 标题、时间、背景和对象。
- 你的角色、具体做了什么，与团队成果的区别。
- 交付物、结果、指标的时间和定义；无数字可用定性反馈。
- 截图/封面/现场照片/论文/作品链接；确认可公开部分。
- 希望呈现哪段判断或复盘；只给链接且不可访问时请用户补内容摘要。

模块间的小选择题：“这个模块的材料？”
- 已给完，继续下一个
- 还要补充
- 这部分不合适，换一个方向

不用等到每个字段填满。一个真实条目有标题和描述，就可以做文字展品；缺图不生成假截图。未说明排名的活动展示序号，不把序号包装成奖项。

### 按材料追加的短问题

- 内容：面向谁？主要讲什么？有什么截图数据？复盘可用“为什么选题—关键取舍—结果—下次调整”。
- 项目：背景—目标—角色—行动—结果；标明某项数字是目标完成率、增长率还是绝对量。
- 科研：完整题目、作者、来源、问题/方法/发现、本人贡献；摘要和进一步推断分开。
- 活动：活动名、团队或个人角色、产出、结果；没获奖也能展示。

## 5. 开工前的内容摘要

用小表列出：名字、简介、模块名称、展示形式、已有条目数、缺口。一次确认即可：
- 按这个方案生成
- 我想调整（自由填写）

所有模块先完成材料收集，再开工 coding；不要用户只给第一个模块，就把余下模块塞进示例内容交付。若用户已明确让你按当前素材直接制作，这可作为确认，不重复询问。

## 状态记录建议

`portfolio-intake.md` 保存在用户项目中：身份/目标、Star 是否已问（不记录凭据）、名称状态、选定模块、各模块材料来源/就绪状态、最终确认。用户新素材只更新相关模块。
