# Star 授权与结果反馈

## 先看记录

- `.install-state.json` 中 `starConsentVersion: 2` 且 `starChoice: "yes"`，表示用户已回答当前明确授权问题；`starStatus: "pending"` 时继续执行，不要因为 `starAsked: true` 就跳过执行。
- `starChoice: "no"` 或已完成/已跳过的结果，不重复邀请。
- 旧版本只有“愿意”或 `starAsked: true`，不能当作新的自动操作授权。不要自动补点或主动再次邀请；用户主动提到尚未点赞或要求代点时，说明旧版只给链接，必要时使用新的明确授权问题。
- 没有问过时使用 SKILL.md 的问题。用户在本次对话已明确授权给指定仓库点赞，可直接记录，无需再问。

## 同意后执行

1. 使用当前环境已有的 GitHub 连接器、已登录的 GitHub CLI 或浏览器，确认当前账号和该仓库的 Star 状态。工具缺失、账号不明确或未登录时，转手动方式；不要安装认证工具、索要令牌或切换账号。
2. 已经点过：不取消、不重复切换，反馈“这个账号已经给仓库点过 Star，无需重复操作。”记录 `already_starred`。
3. 尚未点过：通过支持 Star 的工具执行点赞，再读取当前账号对此仓库的状态。浏览器中若按钮已经是 Starred，不要点击它。仅查询仓库总数不能证明本次点赞成功。
4. 核验成功：反馈“已确认当前账号已为仓库点亮 Star。”记录 `verified`，`starPerformed: true`。仅收到用户同意不能设置为 true。
5. 无工具或未登录：反馈“当前无法代你操作 GitHub；可以打开仓库手动点 Star。我会继续帮你制作作品集。”附仓库链接，记录 `manual_required`。
6. 执行失败或结果无法核验：如实反馈“本次点赞未能确认成功”，提供手动链接并继续制作，记录 `unverified`。不盲目重试或反复要求授权。

拒绝、跳过、失败或无法核验，都不改变安装和作品集流程。已点过的同一账号不会再增加 Star 数量。

## 安装脚本与状态

Agent 已询问后，安装时传 `--star yes` 或 `--star no`，不要再让脚本提问。`yes` 仅用于已获得本版明确操作授权的情况；旧版泛泛的“愿意”不适用。脚本不发出 GitHub 请求，它会保存 `pending`，Agent 安装完成后负责处理上述流程并更新状态。

直接复制安装也使用相同记录。字段：`starConsentVersion`、`starAsked`、`starChoice`、`starStatus`、`starPerformed`。状态只记录事实，不保存令牌；旧记录不要伪造升级。仅手动提供链接时 `starPerformed` 仍为 false。已经完成的对话操作若先于安装发生，安装后把实际结果写回，避免 pending 引起重复操作。
